# Yota Tariff Parser

Python-парсер архивных тарифов [Yota](https://archive.yota.ru). Перебирает заданный диапазон номеров, находит тарифы с **безлимитными ГБ и положительным остатком** и сохраняет цену, количество и ссылку. После перебора формирует топ самых дешёвых тарифов из всей накопленной истории.

Основные возможности:

- Интервал номеров задаётся в консоли или аргументами командной строки.
- Частота и параллельность запросов настраиваются.
- Новые результаты добавляются к старым без перезаписи истории.
- Размер топа задаёт пользователь; по умолчанию — 25 тарифов.
- Одна команда создаёт портативную папку для Windows со встроенным Python.

## Требования

| Задача | Что потребуется |
| --- | --- |
| Запуск из исходников | Windows 10/11, Python 3.10+ и интернет для первой установки зависимостей |
| Сборка портативной версии | Windows 10/11 x64, Python 3.10+ x64; инструменты сборки устанавливаются автоматически |
| Запуск готовой сборки | Windows 10/11 x64; устанавливать Python, pip или браузер не нужно |

Для перебора нужен доступ к серверам Yota. Скорость зависит от сети и ответов сервера.

## Быстрый запуск из исходников

Склонируйте репозиторий или скачайте исходники и откройте PowerShell в папке проекта:

```powershell
.\start.bat
```

Если готового EXE ещё нет, батник найдёт установленный Python, создаст локальное окружение в `.runtime/python`, установит зависимости и запустит парсер. Дальше введите начальный и конечный номера тарифов. **Оба номера входят в диапазон.**

Если Python не найден, установите Python 3.10 или новее и включите `Add Python to PATH` в установщике.

Пример запуска без вопросов в консоли:

```powershell
.\start.bat --start 350 --end 400 --top-count 50
```

После сборки корневой `start.bat` запускает EXE из `bin`. Чтобы запускать именно изменённые исходники, используйте:

```powershell
.\scripts\start-source.bat --start 350 --end 400
```

## Где менять параметры

Правьте **`settings.ini` рядом с `start.bat`**. В исходном проекте это корневой файл, в готовой сборке — `dist/YotaParser/settings.ini`. Настройки читаются при каждом запуске; пересобирать EXE после их изменения не нужно.

```ini
[parser]
requests_per_second = 10
parallel_requests = 3
connect_timeout_seconds = 5
timeout_seconds = 25
network_retries = 2
top_count = 25
mode = api
browser_delay_seconds = 1
output = results/tariffs.txt
```

| Настройка в INI | Аргумент CLI | Назначение и допустимые значения |
| --- | --- | --- |
| `requests_per_second` | `--rate` | Максимум запросов в секунду, включая повторы; больше 0, не больше 1000 |
| `parallel_requests` | `--workers` | Число одновременных API-запросов; целое от 1 до 200 |
| `connect_timeout_seconds` | `--connect-timeout` | Время на установление соединения в секундах; больше 0 |
| `timeout_seconds` | `--timeout` | Общий таймаут запроса в секундах; больше 0 |
| `network_retries` | `--retries` | Повторы временных ошибок; целое от 0 до 5 |
| **`top_count`** | **`--top-count`** | **Сколько самых дешёвых уникальных тарифов сохранять; целое больше 0** |
| `mode` | `--mode` | `api` — быстрый режим; `browser` — проверка SVG из исходников |
| `browser_delay_seconds` | `--delay` | Пауза между страницами в браузерном режиме; секунды, от 0 |
| `output` | `--output` | Путь к накопленному файлу результатов |

Аргументы CLI имеют приоритет над INI и действуют только для текущего запуска. Например, сохранить 10 тарифов в топе при скорости 5 запросов/с:

```powershell
.\start.bat --start 350 --end 400 --rate 5 --workers 3 --top-count 10
```

Начальный и конечный номера задаются парой `--start` / `--end`. Без этой пары программа запросит диапазон сама. Можно выбрать другой файл настроек:

```powershell
.\start.bat --config .\my-settings.ini --start 350 --end 400
```

Путь `output`, если он относительный, считается **от папки программы**, независимо от текущей папки консоли. Путь к файлу, переданному через `--config`, считается от текущей папки консоли. Абсолютные пути также поддерживаются.

## Результаты и топ тарифов

По умолчанию файлы находятся в `results`:

| Файл | Содержимое |
| --- | --- |
| `tariffs.txt` | Все найденные тарифы. Каждая новая проверка добавляет строки; предыдущие сохраняются |
| `top_tariffs.txt` | До `top_count` самых дешёвых уникальных тарифов из всего `tariffs.txt`; обновляется после перебора |
| `tariffs.errors.txt` | Ошибки номеров из последнего перебора с ошибками |
| `crash.log` | Подробности неожиданной ошибки, если она возникнет |

TXT имеет кодировку UTF-8 с BOM. В каждой строке три столбца, разделённые табуляцией:

| Цена, руб. | Осталось, шт. | Ссылка |
| --- | --- | --- |
| 172.43 | 9 | `https://archive.yota.ru/tariff/305` |

В остатке может быть текст `много`. В топе учитывается последняя сохранённая строка по каждой ссылке. Порядок: цена по возрастанию, затем остаток по убыванию, затем номер тарифа по возрастанию. Если подходящих уникальных тарифов меньше, чем `top_count`, файл содержит все доступные.

Топ строится из сохранённой истории: старые цены и остатки могли измениться со времени проверки. Обновить топ без нового перебора можно так:

```powershell
.\start.bat --top-only --top-count 50
```

При собственном `--output`, например `results/custom.txt`, топ будет сохранён рядом в `results/top_custom.txt`, а ошибки — в `results/custom.errors.txt`.

## Сборка одной командой

Откройте PowerShell в папке проекта и выполните:

```powershell
.\build.bat
```

В CMD команда — `build.bat`. При первой сборке автоматически создаётся локальное окружение и устанавливаются зависимости и PyInstaller. Глобальные пакеты Python менять не нужно.

Результат — **`dist/YotaParser`**:

```text
YotaParser/
├── start.bat
├── settings.ini
├── README.txt
├── bin/
│   ├── YotaParser.exe
│   └── _internal/
└── results/
```

Для запуска дважды нажмите `start.bat` в этой папке. Для переноса на другой ПК копируйте **папку целиком**, включая `bin/_internal`. Python уже входит в сборку. Архивировать её при необходимости нужно самостоятельно: команда сборки архивов не создаёт.

Повторная сборка обновляет программу и копирует настройки из корневого `settings.ini`. Результаты в `results` исходного проекта и в `dist/YotaParser/results` сохраняются; история из исходного проекта автоматически в сборку не копируется. Чтобы перенести историю, скопируйте нужный `tariffs.txt` в папку `results` готовой версии.

При сборке тесты, парсер и запросы к Yota не запускаются. Временные файлы находятся в `.build`, локальное окружение — в `.runtime`; Git их игнорирует.

## Режимы и обработка ошибок

`api` использует JSON того же сервера, с которого сайт получает карточки тарифов. Признак `flagUnlimited` соответствует бесконечности возле ГБ. Тариф сохраняется при положительном числовом остатке или надписи `много`.

Перед API-перебором проверяется доступ к серверу. При неудачной предварительной проверке прежние файлы результатов и ошибок сохраняются. Временные сетевые сбои повторяются; при HTTP 429 программа делает паузу и снижает скорость, при 401/403 прекращает перебор. Уже записанные строки сохраняются.

В комплектных настройках установлены 10 запросов/с и 3 одновременных запроса. Снижение скорости не гарантирует устранение уже полученного 403: сервер может отказать и на одиночном проверочном запросе.

Для прямой проверки SVG доступен дополнительный браузерный режим из исходников. Установка Chromium выполняется отдельно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Browser
.\scripts\start-source.bat --mode browser --headed
```

Chromium устанавливается в `.runtime/browsers`. Он не входит в компактный EXE.

Другие команды:

```powershell
.\start.bat --help
.\start.bat --version
.\start.bat --self-check
```

`--self-check` проверяет загрузку программы и зависимостей без обращения к Yota. Ctrl+C останавливает перебор. Без аргументов BAT оставляет окно открытым после завершения; с аргументами возвращает код завершения без паузы.

## Структура репозитория

```text
yota-parser/
├── README.md
├── .gitignore
├── .gitattributes
├── settings.ini
├── start.bat
├── build.bat
├── run.py
├── pyproject.toml
├── requirements*.txt
├── src/yota_parser/
│   ├── cli.py              # аргументы, запуск, создание топа
│   ├── config.py           # чтение и проверка INI
│   ├── api.py              # параллельный перебор через API
│   ├── browser.py          # проверка страницы и SVG
│   ├── output.py           # запись истории и сортировка топа
│   └── paths.py            # пути исходников и EXE
├── scripts/                # настройка окружения и сборка
├── tests/                  # регрессионные тесты
└── results/.gitkeep        # пустая папка результатов
```

В Git входят исходники, настройки, документация и скрипты. Окружения, браузер, готовые EXE, `dist`, кэш и пользовательские результаты исключены через `.gitignore`.

Тесты запускаются отдельно, по желанию, из папки проекта с настроенным локальным окружением:

```powershell
$env:PYTHONPATH = "$PWD/src"
.runtime/python/Scripts/python.exe -m unittest discover -s tests -v
```

Набор использует подменённые ответы API и временные файлы для проверки обработки ошибок, сохранения истории, сортировки и параметров топа.

## Публикация на GitHub

Создайте пустой репозиторий на GitHub. Для первой публикации выполните в папке проекта, заменив `USERNAME/REPOSITORY` своим адресом:

```powershell
git init -b main
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Если локальный репозиторий уже инициализирован, повторять `git init` не требуется. Готовую папку `dist/YotaParser` можно передавать отдельно или вручную прикладывать её архив к GitHub Release; бинарные файлы не добавляются в исходный репозиторий.
